# خوانا — Interview Runner (دو تب مستقل)

یک رابط سبک HTML/CSS/JavaScript برای مصاحبه فنی. Markdown Reader اصلی خوانا در مسیر ریشهٔ ریپازیتوری بدون تغییر باقی می‌ماند.

## راه‌اندازی

از ریشه ریپازیتوری اجرا کنید:

```bash
python3 -m http.server 8765 --bind 127.0.0.1
```

صفحهٔ `http://127.0.0.1:8765/interview/` را باز کنید؛ این مسیر به نمای مصاحبه‌گر هدایت می‌شود.

۱. فایل **خصوصی JSON** بانک سؤال‌ها، پاسخ‌ها و Hintها را فقط در تب مصاحبه‌گر بارگذاری کنید.
۲. دکمهٔ «بازکردن تب کاندیدا» را بزنید؛ فقط همین تب را Screen Share کنید.
۳. سؤال‌ها را با دکمه‌های «قبلی/بعدی» در هر دو تب عوض کنید. تغییر سؤال در هر تب، تب دیگر را نیز هماهنگ می‌کند.
۴. Hintها و سؤال‌های تکمیلی تنها با کلیک مصاحبه‌گر و **یکی‌یکی** نمایش داده می‌شوند.
۵. در تب مصاحبه‌گر پاسخ و Rubric را باز کنید، امتیاز و یادداشت بدهید و خروجی JSON ارزیابی بگیرید.

## تفاوت دو نما

- **کاندیدا:** فقط متن درشت سؤال اصلی، اطلاعات لازم برای صورت مسئله و کد زیر آن، شمارهٔ سؤال و تعداد باقی‌مانده، راهنمای آزادشده و سؤال پیگیری آزادشده، و کلیدهای قبلی/بعدی.
- **مصاحبه‌گر:** علاوه بر موارد بالا، عنوان فنی سؤال، زمان هدف، فهرست موضوعی سمت راست، پاسخ مرجع، Rubric، Hintهای مخفی‌شده، یادداشت، امتیاز و خروجی ارزیابی.

دادهٔ سؤال‌های خصوصی در **هیچ‌کدام از فایل‌های ریپازیتوری عمومی** قرار ندارد. Candidate View بانک سؤال خصوصی را Load نمی‌کند و پیام‌های بین دو تب با `BroadcastChannel` فقط شامل صورت سؤال جاری و Hintهای بازشده هستند.

## محرمانگی و محدودیت‌ها

**فایل خصوصی JSON، پاسخ‌ها و خروجی ارزیابی را به GitHub عمومی، Pages یا هاست عمومی Commit/Upload نکنید.** بستهٔ کامل آفلاین شامل فایل خصوصی را جداگانه و امن نگهداری کنید.

همگام‌سازی برای **دو تب همان مرورگر و Origin یکسان** طراحی شده است؛ نیازی به Backend، WebSocket و Cloud نیست. از آدرس `http://127.0.0.1` در هر دو تب و یک پورت یکسان استفاده کنید، نه `file://`.

این ابزار برای Share کردن تب کاندیدا در همان کامپیوتر مناسب است، نه برای دادن URL به فرد روی دستگاه دیگری. اگر کاندیدا به خود کامپیوتر یا فایل خصوصی دسترسی داشته باشد، جداسازی داده امنیت ایجاد نمی‌کند.

یادداشت و پیشرفت در `sessionStorage` همان تب مصاحبه‌گر ثبت می‌شود؛ بعد از Refresh بانک JSON را مجدد بارگذاری کنید. برای نگهداری بلندمدت حتماً خروجی ارزیابی را ذخیره کنید.
